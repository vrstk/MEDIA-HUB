# Media Hub

Независимое Android-приложение (Kotlin / Jetpack Compose / Material 3).

**Текущий этап: Milestone 1 — подключение облаков (частично).** Это ранний исходный код, а не полностью готовый продукт.

## Уже есть
- Русский интерфейс, 5 вкладок, тёмная и светлая темы.
- Реальный просмотр локальной папки Android через Storage Access Framework с сохранением разрешения, открытием файлов и созданием папок.
- Контракты облачных провайдеров и Room entities как основа архитектуры.
- Проверяемая политика передачи: исходник MOVE не может быть удалён без подтверждения и проверки содержимого.
- GitHub Actions для `testDebugUnitTest` и `assembleDebug`.

## Ещё не реализовано
- Google Drive OAuth, двусторонний перенос и очередь задач.
- Mail WebDAV: реализованы проверка подключения, просмотр папок, создание папок, загрузка и скачивание файлов через Android SAF. Не проверено с реальным аккаунтом Mail; возможны ограничения сервера. Пароль внешнего приложения хранится в Android Keystore с AES-GCM.
- При совпадении имени WebDAV PUT использует If-None-Match: *; автоматической перезаписи нет.
- Загрузка архивного seed в Room (исторические метаданные остаются вне APK).
- Веб-импорт, распознавание похожих лиц, синхронизация.
- Google OAuth и защищённое хранение Google-токенов пока отсутствуют. Учётные данные Mail вводятся только в экран подключения Mail и сохраняются локально в шифрованном виде.

## Сборка
- JDK 17, Android SDK API 36, Android Gradle Plugin 8.13.2, Gradle 8.13, Kotlin 2.4.21.
- Откройте репозиторий в Android Studio, синхронизируйте Gradle и соберите `app:assembleDebug`.
- В CI используется `gradle/actions/setup-gradle@v4`, Gradle 8.13. Отсутствие закоммиченного Gradle Wrapper пока является задачей bootstrap.
- APK после **успешного** запуска Actions доступна в разделе Artifacts соответствующего запуска.

## Безопасность
Не вводите пароли и токены в Issues и Actions. Приложение не сканирует хранилище без выбранной пользователем папки. Оригиналы не удаляются автоматически.

Пакет-спецификация `Media_Hub_Project_Pack_v1.0.zip` является отдельным локальным исходным материалом. Персональный каталог и пользовательские файлы не помещаются в публичный репозиторий.


## Исправление 0.2.1 (14.11.2026)
- Исправлена ошибка Android при попытке задать неподдерживаемую функцию XML-парсера `http://apache.org/xml/features/disallow-doctype-decl`.
- Запрещены DTD/ENTITY-декларации и загрузка внешних XML-ресурсов; добавлены JVM-тесты на некорректный ответ.
- Сборка и unit-тесты проверяются GitHub Actions. Реальная авторизация Mail остаётся для теста на устройстве с пользовательским аккаунтом.

## Обновление 0.2.2
- Экран Mail теперь использует одну вертикальную прокрутку. Исправлена вложенная прокрутка длинных каталогов.
- Длинные URL больше не выводятся в виде %D0/%20: навигация работает через кликабельные хлебные крошки.
- Поиск по именам текущей папки, счётчик объектов, компактные двухстрочные карточки.
- Фото JPG/PNG/WEBP открываются по нажатию для одиночного предварительного просмотра (ограничение: 16 МБ на запрос). Для скачивания доступны отдельные кнопки.
- Предпросмотр не строит массовые миниатюры и не загружает весь каталог на устройство; это не полноценная плиточная галерея.
- Google Drive и двусторонняя передача ещё не реализованы. Реальные операции Mail, кроме подтверждённой навигации, требуют проверки на устройстве.


## Исправление 0.2.3
- Экран Mail теперь полностью заключён в собственный контейнер Compose Column, устраняющий наложение полей формы внутри родительского Box.
- Список файлов использует один LazyColumn с ограниченной высотой через Modifier.weight(1f).
- Кликабельные хлебные крошки для длинных WebDAV-путей отображают декодированные названия папок, не меняя сетевых путей.
- Поиск по текущей папке, двухстрочные названия, просмотр одного JPG/PNG/WEBP с ограничением 12 МиБ и скачивание через Android SAF.
- Подключение по WebDAV и локальное защищённое хранение Mail остаются, но реальное обновление APK может сбрасывать данные из-за смены debug-подписи в GitHub Actions.
- CI автоматически подписывает debug APK временным ключом; для надёжных обновлений с сохранением данных требуется постоянный ключ подписи, хранящийся только в GitHub Actions secrets (не в публичном репозитории).

## MEDIA HUB v0.3.0 — первый плиточный просмотр Mail
- В папках Mail появился выбор **Список / Плитка**.
- В режиме плитки изображения JPG/JPEG/PNG/WEBP запрашиваются по мере появления на экране. Автоматическая загрузка всей библиотеки не запускается.
- Миниатюры декодируются до небольшого размера, сетевые запросы ограничены двумя одновременно, используется in-memory cache 16 МиБ; размер отдельного ответа ограничен 5 МиБ.
- Большие или неподдерживаемые изображения показываются без миниатюры; исходник по-прежнему можно открыть отдельно или скачать.
- Просмотр одиночных изображений, поиск, скачивание, навигация и создание папок Mail сохранены.
- **Пока не реализовано:** OAuth Google Drive, двусторонний перенос целых папок, очередь задач, офлайн-библиотека и распознавание сходства лиц.
- Для проверки режима сетки откройте Mail, найдите папку с JPG и выберите «Плитка».

## MEDIA HUB v0.3.1 — компактный браузер Mail
- Верхняя панель сокращена: путь, назад, обновление и список/плитка доступны без длинного блока кнопок.
- Поиск, создание папок, загрузка файла и отключение Mail находятся под кнопкой «Действия».
- Состояние прокрутки списка и сетки сбрасывается при смене папки, поиска или режима просмотра.
- Неизобразительные файлы и папки в плитке отображаются с отдельными значками; превью для них не запрашивается.
- Секреты и данные пользователя не включаются в публичный репозиторий.
